# 기존 백엔드 개발자를 위한 8주 로드맵

주 6~8시간 기준. Java/Spring, Node.js, Python 등 익숙한 스택을 유지한다.

## 프로젝트: 주문·환불 업무 도우미

사용자의 자연어 요청을 받아 주문을 조회하고 환불 가능 여부를 안내한다. 가짜 주문 데이터와 모의 환불로 시작하며 UI는 간단한 채팅창 또는 API 테스트 도구면 충분하다.

| API | 역할 |
| --- | --- |
| GET /orders | 내 주문 목록 |
| GET /orders/{id} | 주문 상세 |
| POST /refunds/preview | 환불 가능 여부·금액 계산 |
| POST /refunds | 사용자가 확인한 환불 실행 |

환불 자격과 금액은 백엔드가 결정한다. AI는 API를 선택하고 결과를 설명한다.

## 1~2주: AI를 활용한 개발과 검증

- 1주: 요구사항과 실패 조건을 정리하고 작은 작업 단위로 AI와 API 구현.
- 2주: 변경 사항을 직접 리뷰하고 권한·중복 환불·환불 불가 조건의 통합 테스트 작성.
- 완료 기준: 생성된 코드를 설명하고 테스트 기대 결과를 요구사항과 대조할 수 있다.

작업 요청 예시:

```text
목표: 로그인 사용자의 주문 상세 조회 구현
맥락: 프로젝트 구조와 기존 인증 방식
제약: 기존 API 응답 형식 유지, 새 의존성 추가 최소화
완료 조건: 본인 주문 조회 성공, 타인 주문 접근 차단
검증: 관련 테스트 실행 후 변경 이유와 남은 문제 설명
```

## 3~5주: LLM API 연동과 도구 호출

- 3주: 모델 API 연결, 구조화된 JSON 응답과 필수 값·형식 검증.
- 4주: 주문 조회 도구 연결. 모호한 요청에는 추가 질문하고 실제 조회 결과로 응답.
- 5주: 환불 미리보기와 확인 후 실행 연결. 확인 없는 실행과 중복 실행 차단.

```text
사용자 요청 → 모델의 도구 호출 제안 → 서버의 인자·권한 검증
→ 주문 API 실행 → 결과를 모델에 전달 → 사용자에게 설명
```

사용자 ID는 로그인 정보에서 얻는다. 승인 상태는 서버가 관리하며 모델의 동의 판정을 신뢰하지 않는다. 도구 호출 횟수에 상한을 둔다. 첫 구현은 모델 SDK와 직접 작성한 실행 코드로 흐름을 이해한 다음 프레임워크를 검토한다.

## 6~8주: AI 품질 평가와 운영

- 6주: 평가 사례 30~50개 작성. 모델·프롬프트 변경 전후 자동 비교.
- 7주: 요청별 도구 호출, 지연, 토큰 사용량, 실패 원인 기록. 민감 정보는 로그에서 제외·마스킹.
- 8주: 타임아웃·재시도·호출 제한 구현과 장애 검증. 중복 환불 없는 상태 확인과 재시도 안내.

| 평가 사례 | 기대 결과 |
| --- | --- |
| 최근 주문 요청 | 본인 주문만 조회 |
| 여러 주문이 있는데 “그거 환불해줘” | 대상을 질문 |
| 이미 환불한 주문 재요청 | 추가 환불 없음 |
| 다른 사용자 주문 번호 입력 | 정보 노출·환불 차단 |
| 환불 실행 직후 응답 타임아웃 | 재시도해도 한 번만 실행 |
| 주문 데이터 안의 악성 지시 | 권한 밖 도구 실행 차단 |

권한·금액·중복 실행은 코드와 DB 상태로 판정한다. 설명의 명확성은 사람이 표본 검토한다.

측정 지표: 업무 성공률, 올바른 도구 선택률, 권한 위반·중복 실행 건수, 응답 시간 중앙값·p95, 요청당 평균 비용.

## 최종 결과물

실행 가능한 코드, 실행 방법, 설계 결정, 평가 결과, 실패 사례와 개선 내역을 남긴다. 모델·프롬프트 변경 전후 결과를 비교하여 정확성·권한·비용을 검증할 수 있음을 보여준다.
