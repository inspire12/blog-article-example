- [홈 목록](https://inspire12.tistory.com): GraphQL 연재와 운영·성능 관련 글을 확인했다.

## 글 한 편의 구성

독자가 겪는 문제 → 환경과 제약 → 원인 가설 → 대안과 선택 이유 → 코드·재현 방법 → 실제 결과 → 한계와 적용하지 않을 조건 → 출처·관련 글.

전문성은 용어의 양보다 설명과 증거의 연결로 드러낸다. 성능 개선 수치를 넣을 때는 환경·부하 조건·표본·측정 방법을 함께 남긴다. 결과가 없으면 예상 또는 실험 계획이라고 표시한다. 다른 사람의 글을 소개할 때는 원저자의 주장과 내 경험·해석을 구분한다.

## 발행 기록 양식

주제 / 초안 경로 / 검증 코드·커밋 / 검토 상태 / 티스토리 URL / 발행일 / 마지막 사실 확인일 / 수정 이유.

기존 글은 원문을 먼저 검토하고 수정안을 만든다. 새로운 발행이나 수정이 완료된 것처럼 기록하지 않는다.

## 절별 도식과 Spring 예제

사용자 작성 방향(2026-10-24): 글의 한 부분이 완성되면 관련 이미지·도식과 Spring 기반 예제 코드를 함께 준비한다.

- 본문 → 관련 도식 → Spring 예제 → 요청·응답 확인 순서로 연결한다. 도입·동기처럼 코드가 설명에 도움이 되지 않는 부분은 억지로 구현하지 않는다.
- 기술 도식은 요청 방향, 헤더, 서버·브라우저의 처리 주체가 드러나게 만들고 편집 가능한 원본과 게시용 이미지를 관리한다.
- 새 HTTP 실습 예제는 Spring Boot를 기본으로 한다. 언어와 버전은 구현 시 기존 환경 및 사용자 선호를 확인하고 결정한다. 기존 NestJS 예제는 유지한다.
- 코드에는 실행 방법, curl 또는 브라우저 확인 절차, 예상 결과를 연결한다. 실제 실행 결과는 검증 후 기록한다.
- HTTP Header 1편은 역할 소개 범위를 유지한다. 첫 코드 후보는 Accept와 Content-Type을 구분하는 작은 Controller 예제이며, 캐시·인증의 상세 구현은 후속 편으로 둔다.
