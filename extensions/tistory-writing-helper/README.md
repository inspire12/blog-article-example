# 티스토리 글쓰기 도우미

ChatGPT에서 복사한 표 또는 마크다운 표를 티스토리 붙여넣기용 HTML로 바꾸는 Chrome Manifest V3 확장 프로그램입니다. 별도 빌드나 서버가 필요 없습니다.

## 설치

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 README와 manifest.json이 있는 `extensions/tistory-writing-helper` 폴더를 선택합니다.
5. 확장 프로그램 메뉴에서 **티스토리 글쓰기 도우미**를 고정합니다.

## 자동 붙여넣기 (0.2.0)

기본으로 켜져 있습니다. **ChatGPT에서 표 복사 → 티스토리 기본 모드에서 ⌘V / Ctrl+V**만 하면 됩니다.

기존 설치를 업데이트할 때:

1. `chrome://extensions`에서 도우미의 새로고침 버튼을 누릅니다.
2. 티스토리 글을 먼저 임시저장하고 글쓰기 탭을 새로고침합니다.
3. 사이트 접근 권한을 물으면 티스토리 관리자 페이지에서 실행을 허용합니다.

팝업의 **티스토리에 표 붙여넣을 때 자동 변환** 체크로 켜고 끌 수 있습니다. 설정은 기기에 저장됩니다.

- `https://*.tistory.com/manage/newpost…`와 `/manage/post…` 글쓰기 페이지의 서식 있는 편집 영역에서만 작동합니다. HTML/마크다운 모드의 일반 텍스트 입력란은 건드리지 않습니다.
- HTML 표의 제목 행을 tbody 안으로 옮기고 th를 td로 바꿉니다. 주변 문장, 링크와 셀 내부 서식은 유지합니다. 완전히 비어 있는 열은 제거합니다.
- 편집기가 받는 붙여넣기 이벤트의 HTML 데이터를 바꿉니다. 실제 삽입·정제·실행 취소 처리는 편집기에 맡기며, 시스템 클립보드는 바꾸지 않습니다.
- 병합 셀·중첩 표·파일 붙여넣기는 그대로 통과시킵니다. HTML이 없는 단독 마크다운 표도 지원합니다. 문장과 섞인 마크다운은 내용 누락을 막기 위해 그대로 통과시킵니다.
- 자동 변환이 적용되지 않는 편집기에서는 아래 수동 복사 기능을 사용하세요.

## 수동 사용

1. ChatGPT의 원본 표를 복사합니다. 이미 헤더가 분리된 표 대신 원본을 사용하세요.
2. 확장 프로그램을 열고 입력 칸에 붙여 넣습니다. HTML 표는 자동 변환됩니다. 마크다운은 **표 변환하기**를 누릅니다.
3. 미리보기에서 제목과 내용을 확인합니다.
4. **티스토리용 표 복사**를 누릅니다.
5. 티스토리 글쓰기 **기본 모드**에서 일반 붙여넣기(⌘V / Ctrl+V)를 합니다. 서식 없이 붙여넣기는 사용하지 않습니다.
6. 기본 모드에서 여전히 깨지면 **HTML 복사**를 눌러 티스토리 **HTML 모드**의 원하는 위치에 붙여 넣습니다.

확장 팝업은 다른 곳을 클릭하면 닫히고 입력이 초기화됩니다. 반드시 복사 버튼을 누른 후 티스토리로 이동하세요. 원본 데이터는 저장하지 않습니다.

## 수동 변환의 처리 범위

- 첫 행을 제목으로 사용하고 `thead/th` 대신 `tbody/tr/td/strong`으로 재구성합니다. 의미상 헤더 셀을 시각적인 제목 행으로 바꾸는 호환성 절충입니다.
- 각 셀에 테두리·간격·제목 행 배경을 인라인으로 넣습니다.
- 모든 행에서 비어 있는 열만 제거합니다. 옵션으로 해제할 수 있습니다.
- 여러 표를 지원합니다. 표 밖의 문장은 복사 결과에 포함하지 않습니다.
- HTML 입력은 셀의 텍스트와 줄바꿈만 추출합니다. 링크·이미지·기존 글꼴 등은 보존하지 않습니다.
- 마크다운은 표와 인라인 코드·굵은 글씨를 지원하는 제한적인 변환기입니다. 전체 Markdown 렌더러가 아닙니다.
- 병합 셀과 중첩 표는 오류 메시지를 보여 줍니다. 이미 분리되거나 사라진 헤더를 추측해서 복원하지 않습니다.
- 입력을 수정하면 마크다운으로 다시 해석합니다. 렌더링된 표를 수정하려면 원본에서 수정 후 다시 붙여 넣으세요.

## 권한·개인정보

`clipboardWrite`(수동 복사), `storage`(자동 변환 설정 저장)를 요청합니다. 자동 변환용 콘텐츠 스크립트는 티스토리 관리자 경로와 해당 편집기 프레임에서 실행됩니다. 사용자가 붙여 넣는 데이터만 처리하며 수동 복사 버튼을 누를 때만 시스템 클립보드에 씁니다. 서버 통신, 분석 도구, 원격 코드는 없습니다.

## 검증

`node --test extensions/tistory-writing-helper/table.test.mjs` (저장소 루트에서 실행)

회귀 테스트: 제보된 4열 입력 → 2열 출력, 첫 행 유지, 코드 표기, HTML 이스케이프, 빈 열 옵션, 파이프 문자, 잘못된 열 수, 여러 표.

실제 Chrome 확장 로드·클립보드 붙여넣기·티스토리 임시저장/재열기 검증은 별도로 필요합니다. 티스토리의 정제 동작이 실제 원인인지 아직 확인하지 않았으며, 모든 편집기/스킨에서 호환성을 보장하지 않습니다. 수동 확인 시 예시 넣기 → 복사 → 기본 모드 붙여넣기 → 임시저장 → 재열기 순서로 제목 행과 열 수를 확인하세요. Chrome 웹 스토어에는 게시하지 않았습니다.

공식 참고: [확장 프로그램 로컬 설치](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world), [권한 목록](https://developer.chrome.com/docs/extensions/reference/permissions-list).

## 개발

자동 변환 코드를 수정한 뒤 `node extensions/tistory-writing-helper/build.mjs`로 `content.js`를 다시 생성하고 확장 프로그램과 티스토리 탭을 새로고침합니다. 생성 파일도 저장소에 포함하여 설치 시 빌드가 필요 없게 합니다.

`browser-test.html`은 브라우저 DOM 기반 회귀 테스트입니다. 로컬 HTTP 서버로 폴더를 제공한 뒤 열어 PASS/FAIL을 확인할 수 있습니다. 실제 티스토리 통합 테스트를 대신하지 않습니다.

콘텐츠 스크립트 및 편집기 프레임 구성 참고: [Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).

## Vivaldi / 0.2.1 수정

데스크톱 Vivaldi에서도 설치할 수 있습니다. `vivaldi://extensions`에서 개발자 모드를 켜고 이 폴더를 로드합니다. 기존 설치는 새로고침 후 버전 **0.2.1**을 확인하고, 작성 중인 글을 임시저장한 뒤 티스토리 탭도 새로고침합니다. Chrome에 설치한 확장 프로그램은 Vivaldi에 별도로 설치해야 합니다.

0.2.0은 ISOLATED 실행 환경에서 이벤트 속성을 덮어썼으므로 페이지 편집기가 변경된 데이터를 보지 못할 수 있었습니다. 0.2.1에서는 붙여넣기 처리를 MAIN 실행 환경으로 옮기고, 설정 저장은 ISOLATED 스크립트에 남겼습니다. 두 환경 사이에는 켜짐/꺼짐 값만 전달합니다. 기존 브라우저 단위 테스트는 이 실행 환경 차이를 검증하지 못했습니다.

실제 티스토리 편집기에서의 성공 여부는 여전히 별도 확인이 필요합니다. 사이트가 이벤트 데이터를 사용하지 않고 브라우저 기본 붙여넣기에 의존하면 변환이 적용되지 않을 수 있습니다.

[Vivaldi 공식 확장 프로그램 안내](https://help.vivaldi.com/desktop/appearance-customization/extensions/)

## 0.2.2 수정

페이지에서 늦게 생성되는 편집기 iframe에도 상위 문서가 직접 paste 리스너를 연결합니다. TinyMCE 인스턴스를 찾으면 `undoManager.transact`와 `insertContent`로 변환한 표를 한 번 삽입하고 기본 붙여넣기를 취소합니다. HTML 래퍼에 담긴 단독 마크다운 표도 처리합니다. 다른 편집기는 기존 이벤트 데이터 교체 방식으로 동작합니다.

Vivaldi에 0.2.2 로드를 확인했으나, 실제 글쓰기 탭 새로고침에서 미저장 경고가 나타나 취소했습니다. 해당 탭의 실제 붙여넣기 및 저장 후 재열기는 미검증입니다. 브라우저 회귀 테스트의 TinyMCE는 API 모형이므로 실제 티스토리 통합 검증과 구별해야 합니다.

## 0.2.3 실제 티스토리 검증

실제 Vivaldi에서 설정 활성화, 상위 문서 리스너, 편집기 iframe 표식을 확인했으나 프레임의 paste 리스너가 사라진 상태를 확인했습니다. 문서 재작성 후 같은 Document 객체라는 이유로 재연결을 건너뛰던 문제를 수정했습니다. iframe load 때 기존 리스너/옵저버를 정리하고 다시 연결합니다.

2026-10-25 Vivaldi의 티스토리 기본 모드에서 0.2.3으로 확인한 결과: 사용자가 제시한 마크다운 표와 동등한 thead/th HTML 표 모두 헤더를 포함한 4행·2열로 자동 삽입됨. 마크다운 삽입은 한 번의 실행 취소로 제거됨. 테스트 표는 편집 화면에 남겨 두었으며 발행하지 않았습니다. 저장 후 재열기는 확인하지 않았습니다. `document.open/write/close`로 같은 프레임 문서를 재작성하는 회귀 테스트를 추가했습니다.
