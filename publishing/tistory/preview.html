HTTP Header 표 서식

티스토리용 HTML과 공통 CSS를 적용한 로컬 미리보기입니다. 실제 스킨에서의 표시와는 차이가 있을 수 있습니다.

HTTP Header 역할과 핵심 헤더
역할함께 볼 핵심 헤더
표현 선택·해석Accept, Content-Type, Accept-Language
압축Accept-Encoding, Content-Encoding
캐시·재검증Cache-Control, ETag, If-None-Match, Vary
인증Authorization, WWW-Authenticate
상태 유지Set-Cookie, Cookie
다른 출처의 응답 읽기Origin, Access-Control-*
브라우저 보안 정책Content-Security-Policy 등
이동·다운로드·부분 조회Location, Content-Disposition, Range

HTTP Header를 역할별로 묶어 보기

요청은 클라이언트에서 서버로, 응답은 서버에서 클라이언트로 보내는 방향입니다. 아래 분류는 기능을 이해하기 위한 묶음이며, 하나의 헤더가 여러 역할에 쓰일 수 있습니다.

작은 화면에서는 표를 좌우로 밀어 확인할 수 있습니다. 아래 확인 항목은 실습 계획이며 실제 실행 결과가 아닙니다.

표현 선택과 압축
역할함께 볼 헤더구현·확인할 동작
표현 선택·해석: 어떤 형식·언어를 주고받나?요청 Accept, Accept-Language
요청·응답 Content-Type
응답 Content-Language, Vary		구현: 지원하는 표현 선택과 본문 파싱
확인: 요청 선호, 실제 본문, 응답 타입·언어 비교
압축: 같은 내용을 더 적은 바이트로 보내나?요청 Accept-Encoding
응답 Content-Encoding, Vary
Content-Length가 있다면 함께 확인		구현: 지원하는 압축 방식 선택과 실제 압축
확인: 헤더뿐 아니라 압축 바이트·복원 결과 비교
캐시와 재검증
역할함께 볼 헤더구현·확인할 동작
캐시: 저장·재사용·재검증은 언제 하나?요청·응답 Cache-Control
응답 ETag, Last-Modified, Vary, Date, Age
요청 If-None-Match, If-Modified-Since		구현: 캐시 정책 설정과 조건부 GET 처리
확인: 저장된 응답 재사용 여부, 재검증 요청, 200·304와 본문
인증과 상태 유지
역할함께 볼 헤더구현·확인할 동작
인증: 어떤 자격 증명을 요구·제출하나?응답 WWW-Authenticate
요청 Authorization		구현: 서버에서 자격 증명 검증
확인: 인증 정보 없는 요청·잘못된 요청·유효한 요청 비교
상태 유지: 이전 요청과 어떻게 연결하나?응답 Set-Cookie
요청 Cookie		구현: 쿠키 발급과 후속 요청의 세션 조회
확인: 브라우저 저장 상태와 실제 후속 요청
브라우저 정책
역할함께 볼 헤더구현·확인할 동작
CORS: 다른 출처의 스크립트가 응답을 읽어도 되나?요청 Origin, Access-Control-Request-Method, Access-Control-Request-Headers
응답 Access-Control-Allow-Origin, Access-Control-Allow-Methods, Access-Control-Allow-Headers, Access-Control-Allow-Credentials, Access-Control-Expose-Headers, Vary		구현: 허용 출처·메서드·헤더 처리
확인: OPTIONS와 실제 요청, 브라우저 fetch 결과
브라우저 보안 정책: 무엇을 로드·실행할 수 있나?응답 Content-Security-Policy
확장 후보 Strict-Transport-Security, X-Content-Type-Options, Referrer-Policy		구현: 이번 실습은 CSP의 스크립트 제한에 집중
확인: 허용·차단된 스크립트와 브라우저 콘솔
이동과 다운로드
역할함께 볼 헤더구현·확인할 동작
이동·다운로드·부분 조회: 어디로 가고 어떻게 받을까?응답 Location, Content-Disposition, Accept-Ranges, Content-Range
요청 Range, If-Range		구현: 리다이렉트·첨부 다운로드·부분 응답을 각각 구현
확인: 상태 코드, 이동 대상, 다운로드, 실제 바이트 범위
캐시 재검증에서 함께 보는 헤더
헤더역할
Cache-Control응답을 저장하고 재사용하는 정책을 전달한다.
ETag응답 표현의 검증자를 전달한다.
If-None-Match클라이언트가 가진 검증자를 조건으로 보낸다.

같은 표현에 대한 조건부 GET 요청에는 서버가 본문 없이 304 Not Modified로 응답할 수 있습니다. 304는 헤더가 아니라 상태 코드입니다.
